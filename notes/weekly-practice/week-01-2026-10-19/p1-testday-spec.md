# 第1周实作规格书：下一次 P1 测试日 Run Plan / Run Sheet

本文件取代 assessment-and-next.md 中“旧案例 session 工作记录”作为下一项交付的安排；此前评价及练习记录保留。不是额外新增一项周任务。

## 1. 目的

为自己的下一次 P1 测试日准备一份能在维修区直接使用的出车计划和执行记录，训练：
- 把已有遥测判断转成有限节次内值得执行的测试。
- 保留每节的车辆状态、实际动作、有效圈和反馈，避免测试信息丢失。
- 根据上一节结果调整下一节，最后作出保留／回退／继续验证的决定。

核心验收是“能安排测试并留下可继续使用的信息”，不考正式报告写作或排版。

## 2. 参考依据与适用性

| 参考 | 用途 |
|---|---|
| [Data for Motorcycles：Setup and Timing PDF](https://www.datamc.org/wp-content/uploads/2019/01/setup_sheet_2.pdf)／[下载页及 Excel](https://www.datamc.org/downloads/) | 借鉴设置、圈时及运行记录结构 |
| [Dave Moss：Race Day Record Sheet](https://davemosstuning.com/wp-content/uploads/2012/02/RaceDaySheet.pdf) | 借鉴天气、胎压、调整时间和起止设置记录 |
| [Dave Moss：Chassis and Suspension Testing Part 1](https://davemosstuning.com/chassis-and-suspension-testing-part-1/) | 借鉴逐节目的、反馈、调整与复测流程 |

本次为根据公开资料制作的 P1 自用改编表，不称为官方标准，不复制参考资料的全部内容，也不把其中具体调校建议直接当作本车指令。现有证据支持摩托车现场使用这些记录；未确认银骥是否单独使用 run sheet，后续按其真实流程调整。

术语：run plan 写预计安排；run sheet 记实际执行；setup sheet 记车辆设置。本次允许前两者合为一张表，通过“计划／实际”栏区分；车辆基准设置只记录一次并用版本引用，不重复抄写。

## 3. 本周范围与工作量

本周交付：一份能带去下次 P1 的测试日工作表，含计划和现场记录空栏。可另附已有关键图或简短设置页，不另交正式工程报告。

准备参考 60–75 分钟：
- 10 分钟：浏览参考表，选择有用字段。
- 15 分钟：选定主要测试问题、比较方案和最小节次安排。
- 20 分钟：用 AI／现有工具整理工作表初版。
- 15 分钟：桌面走读，核对来源、动作与决定分支，冻结 V1。
- 最多15分钟：助手提出不超过三项执行障碍，修订 V2。

昨天的沟通练习已计入本周；上述为书面准备从零开展的参考，允许拆分或顺延，不为了新规格额外要求本周超出原有60–120分钟额度。真实测试日在用户原本计划去 P1 时进行，不要求本周出车，不把驾驶时间算入桌面练习预算。

## 4. 开始制作前的输入

必须固定：
1. 实际使用的车辆、P1 布局和本人采用的弯号／位置标记。
2. 一个有现有数据或实际反馈支持的主要测试问题。
3. A 基线与 B 改变的具体定义，以及为何值得花节次测试。
4. 预计可用节次／每节时长，单人或是否有人协助。日期未定可暂留空，不凭空填写场地方时刻。
5. 能取得的车辆设置、轮胎状态、胎压及采集设备信息。未知项标“待确认／未记录”。

默认候选：P1 连续弯的前段收益与后段出口取舍；由用户最终选择具体动作和现实位置，不强制照搬旧圈号。历史 S06／S08 可作参考，不能当作本次受控 A/B 结果。若本次车辆或布局不同，先确认历史比较是否仍适用。

已有 RaceChrono／Circuit Tools、GPS速度与位置、OBD油门／RPM和可用视频足以起步。只使用本次实际采到且通过检查的通道；无新增传感器要求。G／倾角如引用仍标为计算通道，不声称实测刹车压力或悬挂位移。保留原有时钟、源采样率与对齐方法，不新增不必要的数据处理工作。

## 5. 工作表最低内容

### A. 页首：测试身份与基准

日期（可待定）、车辆／车手、布局、主要问题、A/B定义、基准设置版本、轮胎标识及已知状态、燃油记录方式、当天条件。常量放页首；发生变化时在对应节次记录。

设置项按车上实际可调机构填写，若涉及阻尼，说明调节器、计数基准、方向和单位。第一次不要求改变悬挂，昨天模拟的10／11／12格不能进入真实车况。

### B. 每节一行：计划与实际分开

| 计划栏 | 实际记录栏 |
|---|---|
| 节次／优先级 | 实际 session 与数据文件名 |
| 目的与A/B版本 | 实际执行动作／偏离原因 |
| 车手操作重点 | 实际圈号、有效圈与排除原因 |
| 预计有效圈目标 | 相关条件变化／设定改动 |
| 保持条件及待检查项 | 车手原始反馈：位置、阶段、现象 |
| 回来比较的主指标 | 结果摘要／下一节决定 |

可拆为上下两区或两个工作表，优先手机／打印阅读，不把宽表压成无法阅读的小字。圈时由现有工具导出或引用，不要求现场逐圈手抄全部通道。

### C. 判断规则

- 出车前明确一个主指标和少量解释指标；连续弯可用完整弯组时间为主，前后段时间与固定出口速度作解释。
- 写明如何确认 B 动作执行到位，以及怎样标记交通、明显失误、旗号或通道异常圈。
- 预先给出采用／回退／结果不明的处理办法。数值阈值应有本次波动或测量依据，不能为填表硬造。
- 对多圈结果、车手反馈和条件变化一起判断；方案未执行到位或样本不足时记“未完成有效比较”，不当作性能失败。
- 独自跑时，停好车后先记简短反馈，再看数据；AI可代整理。需要技师核对的实际改动单独标注。

## 6. 测试日安排原则

采用模块式安排，不预设当天一定有四节或六节：
- 首个可用模块：熟悉、采集确认、建立可用 A 基线。
- 中间模块：实施 B，在可用条件内收集重复样本。
- 后续优先模块：条件允许时回到 A，检查时间趋势、适应和条件漂移。
- 余下节次：按结果确认、继续练习或自由跑，不提前塞入更多测试问题。

这是待填的安排框架，不是已经确定的 A/B/A 测试方案。具体圈数、节次和操作由输入决定。A/B/A可以帮助检查趋势，但不自动消除轮胎、气温和适应干扰。若可用节次不够，写清哪些模块未做，保留为探索结果。

驾驶动作可以是协调的整体跑法；记录同时变化的内容，不为追求单变量把指令拆得无法执行，也不把整套跑法收益单独归因于一个动作。

## 7. 交付与验收

### 本周交付

V1与审查后的V2：P1测试日工作表，可用Excel或可打印文档；先确认内容再决定是否需要可填写PDF。助手可制作模板和整理文字，用户负责测试问题、工程决定和最终核对。

验收：
1. 两分钟内能读出测试目的、每个模块安排、A/B区别、回来如何决定。
2. 页首常量与逐节变化分清，计划与实际执行不会混淆。
3. 真实session／圈号能与数据文件及关键图对应；不存在虚构条件或结果。
4. 桌面走读能处理至少一次“交通使目标圈无效”或“B未执行到位”，不用临时重写评价目标。
5. 拟定每节记录约2–3分钟；这是可用性目标，真实使用后核实并删减字段，不宣称已测得效率。
6. 第一版只服务一个主要问题，能删掉对当天行动没有帮助的字段。

### 真实测试日之后（不是本周额外必交）

填入实际执行和结果，在表底补三行：保留了什么、未解决什么、下次做什么。真实使用后才标“现场验证完成”，再决定哪些字段值得长期保留。没有跑满原计划或没有证明改善，也可以形成有效测试记录。

## 8. AI、职责与归档

允许AI转写、压缩、排版、引用数据及检查遗漏。用户先提供／确认工程判断，AI新增假设或方案需标明是否采纳；普通润色不逐句标注。最终数值、指令、版本与决定由用户核对。

职责按实际情况填写：单人时本人兼任骑手与数据角色，按停车后记录→查看数据→更新计划的顺序完成；有协助者时再分配，不能虚设技师或经理。

规格、用户输入、V1／V2及后续执行记录归档于本周目录；真实测试日期单独注明，不因发生在未来而改写本周准备任务的完成时间。成果不得标成银骥内部流程或已为车队执行。
