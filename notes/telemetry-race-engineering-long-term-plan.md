# 赛车遥测与比赛工程长期实作计划

更新日期：2026-10-18  
启动日期：2026-10-19（第 1 周）  
目标：逐步建立参与 GT4 车队数据分析及现场工程工作的实用能力。

## 1. 执行方式

- 每周安排一项练习，预计 60–120 分钟；当前自动任务为每周一晚间约 19:00（中国时间）提供。
- 三条主线轮换，共用每周一项的额度。优先使用现有数据和免费公开资源，不要求每周上赛道或购买设备。
- 每项练习必须包含：明确目标、所需数据与通道、操作步骤、图表或分析成果、具体验收方法，以及向车手／工程师汇报的精简结论模板。
- 这是可持续调整的长期路线。阶段顺序表示前置关系，不设固定结业日期；根据实际成果调整难度、合并或跳过已掌握的部分。
- 分别记录“已安排”“进行中”“已完成”“已验收”。周数经过不代表技能已经掌握；没有反馈时仍可提供合适的下一项，但须列出前置条件。
- 优先形成可复用的数据处理、测试和决策流程，并积累能够展示的工程成果。

## 3. 三条训练主线

| 主线 | 数据与环境 | 训练目标 | 引入方式 |
|---|---|---|---|
| A：真实赛道车手遥测 | 自有 RaceChrono、OBD、GPS、IMU、视频 | 数据质检、驾驶分析、派生通道、现场复盘 | 持续主线 |
| B：模拟赛车工程 | ACC 或现有模拟器，MoTeC i2／AiM（按实际兼容性选择） | 可重复测试、车手反馈、设定验证、run sheet 与耐力赛执行 | 进入 MoTeC 阶段后，约每 3–4 周穿插一次 |
| C：真实比赛策略分析 | Al Kamel 官方 Timing & Scoring 文件 | stint、进站、交通与旗号、策略窗口和情景决策 | 进入 stint／策略阶段后，与 A、B 轮换 |

### A：真实赛道遥测

从时间／距离对齐、数据质量与 lap/sector delta 开始，逐步分析刹车、油门，以及 brake distance、release rate、throttle pickup、corner radius、yaw、exit acceleration 等派生指标。之后迁移到 MoTeC i2／AiM 工作流，并学习 CAN/logger、燃油计算和工程报告。

每项指标先说明定义、单位、数据来源、适用条件和验证方式。无实测刹车压力时，减速度或视频只能作为代理证据，不能当作压力及其释放率；GPS/IMU 推导曲率、yaw 等指标时，需检查设备坐标、姿态及低速噪声。摩托车分析中可迁移的数据处理与验证技能，以及不能直接用于 GT4 的动力学假设，应分别写清。

### B：模拟赛车工程

借鉴 Formula Student Sim Racing、Williams Esports 工程挑战，以及 GT4 耐力赛 run sheet／strategy 案例，训练分析与决策流程。

首次如未配置软件，先完成最小数据导出、导入及质检，不要求额外 DLC。后续轮换：

- Driver performance：刹车、油门、出弯、稳定性及时间损失。
- Setup A/B/A：固定车辆、赛道、起始燃油、轮胎及环境，记录车手熟悉程度与主观反馈，比较 A→B→A，检查适应、消耗和赛道变化的干扰。
- Run sheet、fuel per lap、stint、pit window、driver swap 与策略执行。

可与朋友分别担任 Driver / Data Engineer，同时保留单人方案。模拟器车辆和轮胎物理的结果只在所用环境中成立，迁移到实车前须重新验证。

### C：Al Kamel 真实比赛策略

官方资料入口：

- [FIA WEC](https://fiawec.alkamelsystems.com/)
- [IMSA](https://imsa.alkamelsystems.com/)
- [ELMS](https://elms.alkamelsystems.com/)

选题时确认赛事页面实际存在的文件和使用限制，优先官方 CSV、时间分析与 pit stop 报表。可优先选择 IMSA GTD、WEC LMGT3 或其他适合练习耐力赛工程流程的组别，并说明与目标 GT4 赛事的规则差异。

递进内容：清理车号、组别、车手、lap time、sector、session time、flags、pit events；重建 driver stint 与 pit timeline；分析圈速一致性、交通／黄旗、进站及总时间损失；再进行带假设与敏感度分析的进站窗口、安全车及换人策略模拟。

这些资料属于计时与成绩数据，不是车载遥测。若提供 Replay.txt，应核对其格式并按计时事件流处理，不能当作视频或 GPS／ECU 数据。逐圈时间本身不足以确定油耗、踏板操作或精确轮胎衰减；分析需考虑交通、燃油重量、轮胎、天气及规则等混杂因素。

## 4. 阶段路线与验收成果

下表是选题路线，每行可拆成多周的一项项练习。

| 阶段 | 核心练习 | 建议成果 | 验收重点 |
|---|---|---|---|
| 1：可信比较 | 通道清单、采样间隔、缺失值、时间／距离对齐、圈与分段边界、delta 符号 | 通道质量表；速度与 delta 叠图；分段收益表 | 自比 delta 接近零；终点差与圈时差一致；分段差可回加；记录边界及插值误差 |
| 2：驾驶诊断 | 刹车起点、减速过程、最低速度、接油、出弯及连续弯收益 | 单弯或连续弯对比图；视频证据；下一节测试建议 | 多圈是否重复；视频是否支持；局部收益是否在后续区段丢失；区分观察与原因假设 |
| 3：派生通道 | 计算、滤波、坐标与单位、延迟、参数敏感度 | 可复现的计算说明／脚本；原始与派生通道图 | 单位与量级合理；对噪声及参数变化是否稳健；代理值的边界清楚 |
| 4：专业软件与测试 | MoTeC i2／AiM 导入、工作表与数学通道；模拟器 A/B/A | 可复用分析布局；run sheet；设定比较报告 | 跨软件圈时／通道一致；同一处理可复现；效果与基线波动比较，不以单个最好圈下结论 |
| 5：采集与 logger | 通道需求、采样预算、CAN 定义、时间同步、标定、掉包排查 | 通道字典；采集方案；质检清单；可选离线 CAN 解码示例 | 按已确认的信号定义核对单位、字节序、缩放、偏移及范围；无硬件时先做离线练习 |
| 6：燃油与 stint | fuel per lap、可跑圈数、reserve、stint 长度、pit loss 与换人 | 燃油／stint 表；pit timeline；计时数据重建 notebook 或表格 | 量纲与燃油收支一致；结果对圈速、消耗及进站损失假设的敏感性明确；实测与模拟分开 |
| 7：比赛策略与现场整合 | pit window、traffic、旗号情景、driver swap、更新决策 | 策略情景表；run sheet；简短比赛工程报告 | 用对应年份及赛事规则检查可行性；只使用当时已知信息做决策；与事后最优结果分开评价 |

第一项仍从数据质量、对齐及 delta 的一个小范围任务开始；具体内容应避免重复现有项目已经充分证明的工作。

## 5. 每次练习的标准交付

主体建议控制在一页 A4 风格 Engineering Report / run sheet，图表、代码及数据说明可作为附件。

1. **问题与目标**：本次要支持什么驾驶、测试或策略决定？
2. **数据与条件**：车辆、赛道、session／lap、通道、单位、来源及测试条件。
3. **方法与证据**：关键操作、1–3 张有效图表或结果表。
4. **结果与不确定性**：观察到什么，干扰因素是什么，当前证据允许多强的结论？
5. **工程决定**：下一步做什么；若证据不足，明确需要追加什么测量或测试。
6. **验收与复现**：如何检查计算正确、结论稳定，如何重新生成成果。

汇报模板：

> 在【条件／数据范围】下，观察到【差异及量级】，证据是【图表／通道／视频】。目前主要不确定性为【因素】。建议下一次【具体操作】，通过【比较指标与验收条件】检验。

不要求每次产生“有效提升”；没有显著差异、原假设未获支持、数据不足以决定，都可以是有价值的工程结果。

## 6. 数据与验证原则

- 分清实测、代理估计和模拟；记录采样率、延迟、同步、标定、滤波与不确定性，不能通过插值制造测量精度。
- 涉及软件版本、设备规格、数据接口及赛事规则时查核官方资料；策略模拟注明赛事、年份、输入假设与情景。
- 不杜撰数据、下载链接或规则。没有新赛道数据时复用既有数据，或采用公开样本／明确标记的合成数据。
- 保留可重现的 notebook、脚本或表格；说明软件版本、输入来源及关键参数。
- 公开成果遵守原始资料使用限制，不再散发无权公开的原始数据。
